    学

    做
    写一个小 GPT 的 forward。
    验
    改未来 token，前面位置的 logits 不变。
    讲要点和检查代码
    • Tokenizer 把文本切成 token，再映射成整数 id。Embedding 是一张查找表：id 进去，向量出来，再加上位置信息。形状从 (B, T) 变成 (B, T, C)。
    • Causal attention：位置 t 只能读到位置 ≤ t 的内容。实现上是把注意力分数矩阵的上三角填成 −∞，再做 softmax。
    • 残差连接让每个子层只学「在原来的基础上改多少」：x = x + f(norm(x))。归一化放在子层前面（pre-norm），层数多了也好训。
    • 最后一层把隐状态映射回词表大小，得到每个位置对下一个 token 的 logits，形状 (B, T, V)。
    import torch

@torch.no_grad()
def check_causal(model, vocab_size, T=16, t=8):
    model.eval()                                   # 关掉 dropout，否则两次前向本来就不同
    x = torch.randint(vocab_size, (1, T))
    x2 = x.clone()
    x2[:, t:] = (x[:, t:] + 1) % vocab_size        # 只改位置 t 及之后的 token
    a, b = model(x), model(x2)                     # logits: (1, T, V)
    assert torch.allclose(a[:, :t], b[:, :t], atol=1e-5), "前面的 logits 变了：mask 漏了"
    assert not torch.allclose(a[:, t:], b[:, t:]), "后面的 logits 没变：模型没在看输入"

    两个 assert 缺一不可。只有第一个的话，一个完全不看输入的模型也能通过。

    问自测问答5 题
    为什么改了未来的 token，前面的 logits 不变？什么会破坏这个性质？

    每一层里，位置 t 只从位置 ≤ t 读信息，叠多少层都一样，所以位置 t 的输出和它后面的输入无关。会破坏它的：mask 写反或漏掉，或者用了跨位置做统计的层（比如在序列维度上算均值方差的归一化）。LayerNorm 只在特征维上算，不会破坏。

    attention 分数为什么要除以 √d_k？

    两个 d_k 维向量点积的方差大致随 d_k 增长。不缩放的话分数太大，softmax 接近 one-hot，梯度很小。除以 √d_k 把方差拉回 1 左右。

    pre-norm 和 post-norm 差在哪？

    pre-norm 是 x + f(norm(x))，残差主路上没有归一化，梯度可以直接传回底层，深层网络更稳。post-norm 是 norm(x + f(x))，原始 Transformer 的写法，对学习率和 warmup 更敏感。

    没有位置编码会怎样？

    不带 mask 的 self-attention 分不清顺序：把输入打乱，输出只是跟着打乱。带 causal mask 时，每个位置能看到的 token 数不同，模型能从中推出一部分位置信息，但显式的位置编码仍然是标准做法。

    一个 block 里参数主要在哪？

    注意力有 Q、K、V 和输出投影四个 d×d 矩阵，约 4d²。MLP 是 d→4d→d，约 8d²。所以 MLP 占三分之二左右。词表 embedding 是 V×d，模型很小时它反而是大头。

    学

    讲要点和检查代码
    • 训练目标：输入是 x[0:T]，目标是右移一位的 x[1:T+1]。每个位置都是一次 V 选 1 的分类，loss 是所有位置交叉熵的平均。
    • 随机初始化时，模型对下一个 token 的预测接近均匀，loss 应该在 ln(V) 附近。差得远，说明初始化或 loss 写错了。
    • AdamW 是 Adam 加上和梯度解耦的 weight decay：衰减直接作用在权重上，不经过自适应步长的缩放。
    • 学习率常用 warmup 加 cosine 衰减。梯度裁剪防止个别 batch 把训练带崩。
    • 数据先切分再训练，留出集从头到尾不参与更新。Checkpoint 要存模型、优化器状态和步数，三样都要，否则接着训和没断过不等价。
    import math, torch, torch.nn.functional as F

def loss_fn(model, x, y):                          # x, y: (B, T)，y 是 x 右移一位
    logits = model(x)                              # (B, T, V)
    return F.cross_entropy(logits.flatten(0, 1), y.flatten())

def overfit_one_batch(model, x, y, vocab_size, steps=300, lr=1e-3):
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    model.train()                                  # 这一步把 dropout 设成 0
    first = loss_fn(model, x, y).item()
    assert abs(first - math.log(vocab_size)) < 1.0, f"初始 loss {first:.2f}，应接近 ln(V)"
    for _ in range(steps):
        opt.zero_grad()
        loss = loss_fn(model, x, y)
        loss.backward()
        opt.step()
    assert loss.item() < 0.1, f"一个 batch 都背不下来：{loss.item():.3f}"

@torch.no_grad()
def evaluate(model, batches):                      # 留出集上的平均 loss
    model.eval()
    return sum(loss_fn(model, x, y).item() for x, y in batches) / len(batches)

    阈值 0.1 要看数据：同一个前缀在 batch 里有多种续写时，loss 到不了 0。过拟合通过之后，正式训练时同时看训练 loss 和留出集 loss：两个一起降是在泛化，训练降而留出不降是在背。

    问自测问答6 题
    随机初始化的模型，loss 应该是多少？

    ln(V)。V = 50257 时约 10.8。第一步的 loss 明显高于或低于这个数，先查初始化和 loss 的写法。

    AdamW 和「Adam 加 L2 正则」有什么区别？

    L2 把 λw 加进梯度，之后会被 Adam 的自适应步长缩放，梯度历史大的参数实际衰减得少。AdamW 把衰减从梯度里拿出来，直接按比例缩小权重，每个参数衰减的力度一致。

    为什么先过拟合一个 batch？

    它把问题切成两半。一个 batch 都背不下来，问题在模型、loss 或优化器的接线上，和数据量、超参无关。这个检查只要几秒钟。

    训练 loss 在降，留出集 loss 在升，说明什么？

    模型在背训练集。可以加数据、缩小模型、加正则（dropout、weight decay），或者在留出集 loss 最低的地方停下。

    为什么要 warmup？

    训练刚开始时梯度大、方向不稳，Adam 的二阶矩估计也还不准。一上来就用大学习率容易发散。先用小学习率走一段，等统计量稳定再放大。

    Checkpoint 只存了模型权重，接着训会怎样？

    优化器的动量和二阶矩丢了，学习率调度也不知道走到哪一步。接着训的头一段 loss 常会出现一个尖峰，结果和不中断的训练不一样。

    学

    做

    验
    对同一组留出 prompts 比较训练前后，不只看训练 loss。
    讲要点和检查代码
    • SFT 的 loss 和预训练是同一个，换的是数据：「指令 → 回答」。通常只在回答部分的 token 上算 loss，prompt 部分 mask 掉。
    • LoRA 冻结原权重 W，只学一个低秩的增量：ΔW = (α / r) · B · A。B 从 0 开始，所以刚接上时模型的输出和原来完全一样。
    • 偏好数据是三元组：prompt、好的回答 y⁺、差的回答 y⁻。DPO 的 loss 是 −log σ(β · [(log π(y⁺|x) − log π_ref(y⁺|x)) − (log π(y⁻|x) − log π_ref(y⁻|x))])。
    • RL（策略梯度）的目标是最大化期望奖励 E[r(x, y)]：要在线采样，要有奖励函数。DPO 是离线的，只需要成对比较，形式上是一个二分类 loss。
    • 评估要固定一组没训练过的 prompts 和采样参数，训练前后各生成一次再比。训练 loss 降了只说明拟合了训练集。
    import math, torch, torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base
        for p in base.parameters():
            p.requires_grad_(False)                # 原权重冻住
        self.A = nn.Parameter(torch.empty(r, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))   # B 从 0 开始
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)

base = nn.Linear(64, 64)
x = torch.randn(4, 64)
want = base(x)
lora = LoRALinear(base)

# 检查 1：刚包上 LoRA 时，输出和原来完全一样
assert torch.equal(lora(x), want)

# 检查 2：只有 A 和 B 在训练
assert [n for n, p in lora.named_parameters() if p.requires_grad] == ["A", "B"]

    这段代码只检查 LoRA 接对了。阶段的验收是另一件事：固定留出 prompts 和采样参数，训练前后各生成一次，逐条对比。

    问自测问答6 题
    LoRA 的 B 为什么初始化成 0，A 却是随机的？

    B = 0 让 ΔW 一开始是 0，微调从原模型的行为出发。A 必须非零：如果 A 和 B 都是 0，两边的梯度也都是 0，永远学不动。

    r = 8 的 LoRA 加在一个 4096×4096 的线性层上，多了多少可训练参数？

    A 是 8×4096，B 是 4096×8，一共 65,536 个，是原来 16.8M 的 0.39%。

    DPO 和策略梯度 RL 的目标差在哪？

    RL 直接最大化奖励的期望，需要从当前策略采样，再用奖励给样本加权。DPO 不采样、不需要显式奖励，只让好回答相对差回答的对数概率差变大。它隐含的奖励是 β · log(π / π_ref)。

    DPO 里的参考模型 π_ref 起什么作用？

    DPO 是从「带 KL 约束的奖励最大化」推出来的，π_ref 就是那个约束的锚点，限制模型不要离原来太远。去掉它，loss 只比较两个回答的对数概率，不再约束模型整体漂多远。

    为什么不能只看训练 loss？

    训练 loss 降说明拟合了训练样本，可能是学会了，也可能是背下来了。没见过的 prompt 上行为可能没变，甚至原有能力变差。要在留出 prompts 上比实际生成的结果。

    SFT 时为什么把 prompt 部分的 loss mask 掉？

    目标是「给定指令，生成回答」，不是学会生成指令。prompt 很长时，它的 loss 会盖过回答部分的信号。

    学
    采样、KV cache、prefill/decode、batching；理解量化和并行在省什么。
    做
    实现 KV cache。
    验
    先验证 logits 与无 cache 的版本一致，再量延迟和显存。
    讲要点和检查代码
    • 采样的流程：logits 除以温度 T，按 top-k 或 top-p 截断，softmax，再抽样。T 趋近 0 就是贪心。
    • KV cache：自回归生成时，旧位置的 K 和 V 不会再变，所以每步只算新 token 的 Q、K、V，再和缓存里的 K、V 做注意力。每步的注意力计算量从 O(t²) 降到 O(t)。
    • Prefill 一次前向处理整个 prompt，token 之间可以并行，瓶颈在算力。Decode 每步只出一个 token，却要把全部权重和 cache 读一遍，瓶颈在内存带宽。所以首 token 延迟主要看 prefill，之后每个 token 的延迟看 decode。
    • Batching 把多个请求拼进同一次前向，用单个请求的延迟换整体吞吐。Continuous batching 让请求随时进出，不用等一整批结束。
    • 量化减少每个权重的位数，省的是显存和每步要读的字节数。并行（tensor parallel、pipeline parallel）让单卡放不下的模型能跑，代价是卡之间的通信。
    • KV cache 的大小：2 × 层数 × batch × 序列长度 × 头数 × 每头维度 × 每个数的字节数。
    import torch

@torch.no_grad()
def check_kv_cache(forward, forward_cached, prompt, new_tokens=20):
    # forward(x) -> logits (B, T, V)，每次把整个序列重算一遍
    # forward_cached(x_new, cache) -> (logits, cache)，cache=None 表示从头开始
    x, ref = prompt.clone(), []
    for _ in range(new_tokens):
        last = forward(x)[:, -1]
        ref.append(last)
        x = torch.cat([x, last.argmax(-1, keepdim=True)], dim=1)

    logits, cache = forward_cached(prompt, None)                 # prefill：一次处理整个 prompt
    for i in range(new_tokens):
        last = logits[:, -1]
        assert torch.allclose(last, ref[i], atol=1e-4), f"第 {i} 步 logits 不一致"
        logits, cache = forward_cached(last.argmax(-1, keepdim=True), cache)   # decode：只喂一个 token

    最常见的错：带 cache 时位置编码还从 0 开始算，第 1 步就会对不上。一致性通过之后再量性能：GPU 上计时前后要 torch.cuda.synchronize()，丢掉前几次预热；显存看 torch.cuda.max_memory_allocated()。

    问自测问答7 题
    为什么用了 KV cache，结果和不用完全一致？

    Causal mask 下，旧位置每一层的输出只依赖它之前的位置，新 token 进来不会改变它们，所以它们的 K 和 V 可以原样复用。新位置要用的正好就是这些 K、V。浮点运算顺序不同会带来 1e-5 量级的差别，所以比较时用 allclose。

    为什么只缓存 K 和 V，不缓存 Q？

    位置 t 的 Q 只在算位置 t 自己的输出时用一次。后面的位置用的是它们自己的 Q，去查前面所有位置的 K 和 V。

    Prefill 和 decode 的瓶颈为什么不一样？

    Prefill 一次处理很多 token，矩阵乘法的规模大，GPU 的算力被吃满。Decode 一次只处理一个 token，计算量很小，但每一步仍然要把所有权重和 cache 从显存读一遍，时间主要花在读内存上。

    Temperature、top-k、top-p 各在做什么？

    Temperature 缩放 logits，控制分布有多尖。Top-k 只保留概率最高的 k 个 token。Top-p 保留累计概率刚好超过 p 的最小集合，候选的个数会随分布变化。

    量化省的是什么？

    权重占的显存，以及 decode 每步要读的字节数，所以受内存带宽限制的 decode 也会变快。代价是精度，要用 perplexity 或下游任务确认损失了多少。

    Batch 变大，延迟和吞吐怎么变？

    吞吐上升，直到算力或内存带宽饱和；单个请求的延迟上升。静态 batching 还要等凑齐一批、等最长的那条结束，continuous batching 解决的就是这个。

    12 层、12 头、每头 64 维、fp16，1024 个 token，batch 为 1，KV cache 多大？

    2 × 12 × 1024 × 12 × 64 × 2 字节 ≈ 36 MB。它随序列长度和 batch 线性增长，上下文翻倍就翻倍。

    import json, time

def run_episode(model, env, tools, max_steps=20, timeout_s=10, log_path="run.jsonl"):
    obs = env.reset()
    history = []
    with open(log_path, "w") as log:
        for step in range(max_steps):
            raw = model(history, obs)              # 模型的原始输出，先原样记下来
            rec = {"step": step, "obs": obs, "raw": raw}
            t0 = time.time()
            try:
                action = json.loads(raw)           # 约定格式：{"tool": ..., "args": {...}}
                if action["tool"] == "done":
                    rec["result"] = "done"
                    log.write(json.dumps(rec, ensure_ascii=False) + "\n")
                    break
                result = tools[action["tool"]](env, timeout=timeout_s, **action["args"])
            except Exception as e:                 # 解析失败、未知工具、超时：都回给模型
                result = f"error: {type(e).__name__}: {e}"
            rec.update(result=result, seconds=round(time.time() - t0, 3))
            log.write(json.dumps(rec, ensure_ascii=False) + "\n")
            history.append((obs, raw, result))
            obs = env.observe()
    return env                                     # 成没成功，交给独立检查器看环境状态

    obs 要能写进 JSON：如果是截图，就存成文件，日志里记路径。工具函数自己负责遵守 timeout。

    问自测问答6 题
    工具调用失败时，harness 该怎么办？

    先分类。超时、限流、网络错误：退避后重试，有次数上限。模型的错（参数不对、工具不存在）：把错误原样返回给模型，让它改。环境坏了无法恢复：终止并记录。三种情况都要写日志。

    什么样的动作不能直接重试？

    有副作用而且不幂等的：提交表单、下单、发消息。超时不等于没执行。重试之前先观察环境，确认上一次的结果。

    任务有没有完成，为什么不能听 agent 自己说？

    模型会在没做完时说做完了，也会反过来。完成与否要由独立的检查器去读环境的最终状态来判定。

    日志里至少要有什么，事后才能定位失败？

    每一步模型看到的观察、模型的原始输出、解析出的动作、环境的返回、耗时和错误。缺了原始输出，就分不清是模型说错了还是解析错了。

    上下文越来越长怎么办？

    压缩或丢掉旧的观察，尤其是很大的 DOM 和截图；保留任务说明和最近几步。尽量只在末尾追加：改动前面的内容会让 KV cache 的前缀失效，后面全部要重算。

    为什么强调「可控」的网页？

    为了可复现。每次都能回到同一个初始状态，没有外部变化，检查器能读到真实状态。否则两次运行结果不同，分不清是 agent 的原因还是环境的原因。

    Evals 与面试

    学
    用独立检查器判定任务是否完成。
    做
    固定模型，对比两版 harness。
    验
    每个失败都归进三类之一：规划、工具执行、评分。
    交
    整理一页项目说明，和之前做 agent 评测的经历接起来。
    讲要点和检查代码
    • 检查器独立于 agent：它不读 agent 的自述，只读环境的最终状态（页面、数据库、文件），返回是否通过和原因。
    • 对比两版 harness 时，模型、任务集、采样参数、初始状态全部固定，只换 harness。每个任务跑多次，因为同一个配置的结果本身就会波动。
    • 两版跑的是同一批任务，结果是配对的，要用配对的方法比（McNemar 检验或配对 bootstrap）。只比两个总成功率，看不出差别是不是真的。
    • 失败分三类。规划：模型选错了要做的事（误解目标、步骤错、过早停止）。工具执行：要做的事是对的，动作没落地（参数错、超时、点错元素、解析失败）。评分：agent 做对了却被判错，或者做错了被判对。
    • 归因按顺序排除：先核对检查器（评分），再看动作有没有按意图执行（工具执行），剩下的才是规划。
    • 评分类的问题最先修。检查器有错，其他数字都不可信。
    from collections import Counter

def check_task(env_state: dict, expected: dict):
    """独立检查器：只看环境最终状态，不看 agent 说了什么。"""
    for key, want in expected.items():
        got = env_state.get(key)
        if got != want:
            return False, f"{key}: 期望 {want!r}，实际 {got!r}"
    return True, "ok"

def compare(pass_a, pass_b):
    """同一批任务上两版 harness 的结果，按任务配对。"""
    assert len(pass_a) == len(pass_b)
    n = len(pass_a)
    only_a = sum(a and not b for a, b in zip(pass_a, pass_b))
    only_b = sum(b and not a for a, b in zip(pass_a, pass_b))
    return {"A": sum(pass_a) / n, "B": sum(pass_b) / n,
            "只有 A 过": only_a, "只有 B 过": only_b}    # 两版的差别全在这两个数里

def failure_table(labels):
    """labels 来自人工读日志，每个失败一个：planning / tool / grading。"""
    assert set(labels) <= {"planning", "tool", "grading"}
    return Counter(labels)

    failure_table 的输入要靠读日志得到，这一步没有捷径。

    把失败归成规划、工具执行、评分三类，没有对应的题，要自己读日志。

    问自测问答6 题
    为什么需要独立的检查器？

    Agent 的自述不可靠，用同一个模型给自己打分也会有偏。检查器直接读环境状态，判定标准写在代码里，可以重复运行，也可以被人审查。

    固定模型比两版 harness，还要固定什么？

    任务集、每个任务的初始环境状态、采样参数（温度、seed）、步数和超时预算。工具集也要固定，除非它正是要比的东西。

    A 版成功率 62%，B 版 66%，一共 50 个任务。能说 B 更好吗？

    不能直接说。50 个任务上 4 个点只是 2 个任务。要看配对结果：只有 A 过的和只有 B 过的各有几个；再看同一版重复跑几次，波动有多大。

    拿到一个失败，怎么判断它属于规划、工具执行还是评分？

    先人工看环境的最终状态：任务其实做成了，就是评分问题。没做成，再对照日志里的原始输出和实际执行的动作：模型想做的是对的但没执行成功，是工具执行；模型想做的本身就不对，是规划。

    pass@k 和 pass^k 有什么区别？

    pass@k 是 k 次里至少成功一次，量的是能力上限。pass^k 是 k 次全部成功，量的是可靠性。要上线的 agent 看后者。

    一分钟怎么讲这个项目？

    四句话。做了什么：从训练模型一路做到评测 harness，是一条线。怎么验证：举一个最硬的检查，比如 KV cache 的 logits 一致性。发现了什么：两版 harness 的差别主要来自哪一类失败。和以前的工作有什么联系。
